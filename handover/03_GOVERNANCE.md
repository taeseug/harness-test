## 📋 의사결정 프로세스

### 변경의 3가지 Type

```
🔴 Type A (긴급, 24시간)
   예: 보안 이슈, 시스템 장애
   절차: 즉시 Owner + 리더 → 승인 → 구현
   ADR: 필수
   
🟡 Type B (일반, 1-2주)
   예: 정책 변경, 기준 수정
   절차: Owner에게 제안 → ADR 작성 → 팀 검토 → 승인
   ADR: 필수
   
🟢 Type C (경미, 즉시)
   예: 문서 수정, 예제 추가
   절차: Owner가 바로 수정
   ADR: 불필요
```

### 의사결정 단계

```
1️⃣ 문제/아이디어 발견
   └─ 팀 멤버 또는 Owner

2️⃣ Owner에게 제안
   └─ Slack 또는 회의

3️⃣ Type 분류
   └─ A/B/C 중 선택

4️⃣ ADR 작성 (Type B 이상)
   └─ 04_MEETING_HARNESS 참고

5️⃣ 팀 검토
   └─ 2-3일 피드백

6️⃣ 리더 승인
   └─ 최종 GO

7️⃣ 문서 업데이트
   └─ SSOT + 구체적 파일

8️⃣ 팀 공지
   └─ 회의 또는 Slack

9️⃣ 이력 기록
   └─ 변경 이력 섹션에 추가
```

## 🎯 자주 하는 질문

**Q: SSOT를 수정하고 싶은데?**
A: 담당 Owner에게 제안 → Type 분류 → ADR (필요시) → 승인

**Q: Owner가 아닌데 제안할 수 있나?**
A: 네. Owner에게 제안하면 됨. Type C는 빠르게, Type B는 ADR 필요.

**Q: SSOT와 팀 규칙이 충돌하면?**
A: SSOT가 우선. 다르면 의사결정 프로세스로 조율.

**Q: Owner에게 못 연락되면?**
A: 백업 Owner 또는 리더에게 연락.
