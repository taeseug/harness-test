# 회의 자동화 하네스 (Meeting Automation Harness)

**목표**: 회의 전→중→후 전체 라이프사이클 자동화  
**사용자**: 팀 리더, 의장, 기록자  
**부담도**: 5분 (사용자), 자동화 (Claude)

---

## 📋 빠른 시작 (5분)

### 새로운 회의를 만들려면

```bash
# 옵션 1: 수동으로 템플릿 복사
cp _meeting-template.md 2026-08-XX_주제.md

# 옵션 2: 자동으로 생성 (Claude 하네스)
/claude meeting:create --date 2026-08-XX --topic "모델 선택 논의"
```

### 회의 후 자동 정리

```bash
# 회의록 업로드
/claude meeting:process 2026-08-XX_주제.md

# 자동으로:
# 1. 요약 생성
# 2. 액션 아이템 추출
# 3. SSOT 영향 분석
# 4. ADR 초안 생성 (필요시)
# 5. SSOT.md에 링크 추가
```

---

## 🔄 워크플로우 상세

### Phase 1️⃣: 사전 준비 (Pre-Meeting)

**시간**: 회의 24시간 전  
**담당**: 의장 (10분 소요)

```
1. 주제 결정
   ├─ 주제명: "모델 선택 기준 정의"
   └─ 예상 시간: 60분

2. 아젠다 자동 생성
   ├─ 이전 회의록 참조
   ├─ 관련 SSOT 문서 인출
   └─ 현안 이슈 추출

3. 배경 자료 수집 (자동)
   ├─ [[model-selection.md]] 현재 상태
   ├─ 최근 의사결정 (ADR)
   ├─ 팀 피드백 (미해결 이슈)
   └─ 외부 자료 (모델 비교표)

4. 참석자 알림
   └─ Slack: 아젠다 + 준비 가이드
```

**입력 템플릿**:

```yaml
meeting_title: "모델 선택 기준 정의"
date: 2026-08-17
time: "10:00~11:00"
facilitator: "[이름]"
participants: ["[이름1]", "[이름2]", "[이름3]"]

# 아래는 Claude가 자동 생성
previous_meeting: "2026-08-10_meeting.md"
related_ssot: ["model-selection.md", "evaluation.md"]
pending_issues: ["[이슈1]", "[이슈2]"]
```

### Phase 2️⃣: 회의 진행 (During Meeting)

**시간**: 회의 중  
**담당**: 기록자 (실시간 기록)

```
구조화된 기록 형식:

🎯 안건별로:
├─ 배경 설명 (2분)
├─ 각자 의견 (이름: 의견)
├─ 핵심 포인트 (3-5개)
└─ 가결 또는 보류

⚡ 결정 기록
├─ 결정사항: 명확하게
├─ 근거: 왜 그리 결정했는가
└─ 마감일: YYYY-MM-DD

📌 행동항목
└─ [이름] - [구체적 작업] - 마감 YYYY-MM-DD
```

**기록자 팁**:
- 의견은 "좋다" X → "Sonnet 5로 변경하고 cost 20% 절감" O
- 결정vs의견 구분: "💬 [의견]" / "✅ [결정]"
- 마감일 필수: "누군가 하겠지" X

### Phase 3️⃣: 사후 처리 (Post-Meeting)

**시간**: 회의 후 24시간 이내  
**자동 처리**: Claude 하네스가 담당

#### Step 1: 자동 요약 생성

```markdown
## 📝 회의 요약 (자동 생성)

**핵심 결정**:
- 모델 선택 기준을 3가지로 통일
- Haiku: 경량 작업, Sonnet: 균형, Opus: 복잡 추론

**영향받는 SSOT**:
- [[model-selection]]
- [[prompt-engineering]] (선택한 모델별 최적화)

**마감일 추적**:
- [이름]: Haiku 벤치마크 ~ 2026-08-24
- [이름]: 팀 가이드 작성 ~ 2026-08-31
```

#### Step 2: 액션 아이템 추출 & 추적

```yaml
action_items:
  - id: "MEET-20260817-001"
    owner: "[이름]"
    task: "Haiku 4.5 벤치마크 테스트 (지연시간, 정확도)"
    deadline: "2026-08-24"
    status: "pending"
    ssot_link: "model-selection.md"
    
  - id: "MEET-20260817-002"
    owner: "[이름]"
    task: "팀 가이드 문서 작성 (모델 선택 의사결정 트리)"
    deadline: "2026-08-31"
    status: "pending"
    ssot_link: "GOVERNANCE.md"
```

#### Step 3: SSOT 영향 분석

```
변경 필요한 SSOT:
┌─ [[model-selection.md]] 
│  └─ "모델 선택 기준" 섹션 업데이트
│     (이전: 5가지 → 새로운: 3가지 명확화)
│
└─ [[GOVERNANCE.md]]
   └─ Owner 권한 확대 (빠른 의사결정용)
```

#### Step 4: ADR 초안 생성 (Type B 이상)

```
📌 ADR-002-Model-Selection-Criteria.md (초안)

## Context
- 기존 모델 선택 기준이 모호했음
- 팀에서 5가지 기준으로 혼란스러워함
- 의사결정 시간 지연 (회의당 30분 초과)

## Decision
- 3가지로 명확화: Haiku(경량) / Sonnet(균형) / Opus(복잡추론)
- 각 기준별 체크리스트 작성
- 월간 리뷰에서 추가 기준 검토

## Consequences
- (+) 빠른 의사결정 (회의 시간 30% 감소)
- (+) 신규자 온보딩 용이
- (-) 새로운 모델 출시시 리뷰 필요
```

| ID | 담당자 | 작업 | 마감 | 상태 |
|----|--------|------|------|------|
| MEET-20260817-001 | [이름] | Haiku 벤치마크 | 2026-08-24 | ⏳ 진행 중 |

# 회의 아젠다: 모델 선택 기준 정의

   - 기준 확정
   - 시행 일정

## 🔧 기술 상세

### 하네스 구성

```
Meeting Harness
│
├─ Pre-Meeting
│  ├─ Agenda Generator (이전 회의 분석)
│  ├─ Background Fetcher (SSOT 문서 수집)
│  ├─ Slack Notifier (팀 알림)
│  └─ Calendar Sync (캘린더 동기화)
│
├─ During-Meeting
│  ├─ Meeting Template (구조화된 템플릿)
│  ├─ Real-time Checker (구조 확인)
│  └─ Markdown Validator (형식 검증)
│
└─ Post-Meeting
   ├─ Summary Generator (Claude 요약)
   ├─ Action Item Extractor (액션 아이템 추출)
   ├─ SSOT Analyzer (영향 분석)
   ├─ ADR Generator (의사결정 기록)
   ├─ SSOT Updater (자동 링크 추가)
   └─ Notifier (팀 알림)
```

## 💡 팁 & 트러블슈팅

### 팁

1. **의견 vs 결정 구분**
   - 💬 의견: "Haiku가 빠를 것 같은데"
   - ✅ 결정: "Haiku를 경량 작업에 사용하기로 결정"

2. **구체적으로 기록**
   - ❌ "비용 절감"
   - ✅ "월간 비용 $500 → $200으로 60% 절감 예상"

3. **마감일 필수**
   - ❌ "나중에 벤치마크 진행"
   - ✅ "[이름] - Haiku 벤치마크 - 2026-08-24"

4. **SSOT 링크**
   - [[model-selection]] 처럼 이중 괄호 사용
   - 자동 링크로 변환됨

### 문제 해결

**Q: 회의록이 처리 안 됨**  
A: 파일명 형식 확인 (`YYYY-MM-DD_*.md`), 마크다운 문법 검증

**Q: 액션 아이템이 누락됨**  
A: "- [ ] **[이름]**" 형식 확인, 마감일 입력 확인

**Q: SSOT 링크가 자동 생성 안 됨**  
A: `[[문서명]]` 형식 사용, 문서명 정확히 입력
