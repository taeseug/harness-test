## 📊 모델 성능 매트릭스

### Claude 시리즈 비교

```
┌─────────────┬──────────┬─────────┬─────────┬──────────┐
│ 모델        │ 능력     │ 속도    │ 비용    │ 추천용도 │
├─────────────┼──────────┼─────────┼─────────┼──────────┤
│ Haiku 4.5   │ ⭐⭐⭐⭐  │ ⭐⭐⭐⭐⭐ │ ⭐⭐   │ 경량    │
│ Sonnet 5    │ ⭐⭐⭐⭐⭐ │ ⭐⭐⭐⭐ │ ⭐⭐⭐ │ 균형    │
│ Opus 5      │ ⭐⭐⭐⭐⭐ │ ⭐⭐⭐   │ ⭐⭐⭐⭐⭐ │ 복잡   │
└─────────────┴──────────┴─────────┴─────────┴──────────┘
```

### 자세한 비교

| 특성 | Haiku 4.5 | Sonnet 5 | Opus 5 |
|------|-----------|----------|--------|
| 컨텍스트 윈도우 | 200K | 200K | 200K |
| 입력 토큰 비용 | $0.80/M | $3.00/M | $15.00/M |
| 출력 토큰 비용 | $4.00/M | $15.00/M | $75.00/M |
| 추론 지연시간 | ~300ms | ~500ms | ~800ms |
| 수학 추론 | 좋음 | 매우좋음 | 최고 |
| 코드 생성 | 좋음 | 매우좋음 | 최고 |
| 창의성 | 보통 | 좋음 | 매우좋음 |

## 🎯 선택 기준 (Decision Tree)

```
├─ 비용이 우선?
│  ├─ YES → Haiku 4.5
│  └─ NO ↓
├─ 복잡한 추론 필요?
│  ├─ YES → Opus 5
│  └─ NO → Sonnet 5
```

### 구체적 사용 사례

#### 1️⃣ Haiku 4.5 (경량 작업)

**적합한 경우**:
- 분류, 요약, 간단한 변환
- 높은 처리량 필요
- 비용이 주요 제약
- API 호출 빈도가 높음

**예제**:
```python
# 감정 분석
"이 리뷰의 감정을 classify: [긍정/부정/중립]"

# 스팸 필터링
"이 이메일이 스팸인가? [yes/no]"
```

**규칙**: 
- 기본값으로 Haiku부터 시작
- 성능 부족할 때만 상향

#### 2️⃣ Sonnet 5 (균형)

**적합한 경우**:
- 일반적인 개발 작업
- 비용과 성능의 균형
- 대부분의 프로덕션 워크로드
- 회사 표준 모델

**예제**:
```python
# 코드 리뷰
"이 함수를 review하고 개선점 제안"

# 문서 작성
"이 코드에 대한 설명서 작성"
```

**규칙**:
- 프로덕션 기본값
- Haiku로 부족하면 이 모델 사용

#### 3️⃣ Opus 5 (복잡)

**적합한 경우**:
- 복잡한 추론/분석
- 가장 어려운 문제 해결
- 최고 품질이 필수
- 비용보다 성능 우선

**예제**:
```python
# 아키텍처 설계
"이 시스템 설계의 trade-offs 분석"

# 수학 증명
"이 알고리즘의 시간복잡도 증명"
```

**규칙**:
- Sonnet으로 답변 검증할 때만 사용
- 기본값으로 사용하지 말 것

## 💰 비용 최적화 전략

### Strategy 1: 모델 계층화

```
입력 → Haiku (필터링)
    ├─ 간단 → Haiku 답변
    └─ 복잡 → Sonnet (처리)
           ├─ 확실 → Sonnet 답변
           └─ 불확실 → Opus (검증)
```

**기대 효과**: 비용 50-70% 절감

### Strategy 2: 배치 처리

```
❌ 잘못된 방식
for item in items:
    response = sonnet.generate(item)  # N번 API 호출

✅ 올바른 방식
responses = sonnet.generate_batch(items)  # 1번 API 호출
```

### Strategy 3: 컨텍스트 최소화

```
❌ 전체 코드베이스 제시 (200K 토큰)
✅ 관련 코드만 제시 (5K 토큰)

= 40배 비용 절감
```

## 🔄 모델 선택 의사결정 흐름

### 단계 1: 작업 분류

```
작업의 복잡도는?
├─ 간단 (분류, 검색, 형식 변환)
│  └─ Haiku 시작
├─ 보통 (코드 생성, 요약, 설명)
│  └─ Sonnet 시작
└─ 복잡 (설계, 증명, 분석)
   └─ Opus로 검증
```

### 단계 2: 성능 검증

```
원하는 품질 달성?
├─ YES → 현재 모델 유지
└─ NO → 다음 레벨로 상향 (Haiku → Sonnet → Opus)
```

### 단계 3: 비용 검증

```
비용이 허용 범위?
├─ YES → 확정
└─ NO → Strategy 1-3 적용
```

## 📋 체크리스트

모델을 선택할 때마다 확인:

- [ ] 작업의 복잡도 분류 (간단/보통/복잡)
- [ ] 필요한 레이턴시 확인 (ms 단위로)
- [ ] 예산 제약 확인
- [ ] Haiku로 시작했는가?
- [ ] 실패한 경우만 상향 결정?
- [ ] 배치/컨텍스트 최소화 검토?
- [ ] 이전 결정과 일관성 확인?
