# 📅 [YYYY-MM-DD] [회의 주제]

**복사 후 사용**:
1. 파일명을 `YYYY-MM-DD_주제.md`로 변경
2. 빨간 `[변수]` 부분 채우기 (자동 감지됨)
3. 회의 중 논의 내용 추가
4. 회의 후 `/claude meeting:process [파일명]` 실행

## 💡 SSOT 영향 판단

**언제 ADR을 작성할 것인가?**

- 🔴 **Type A** (긴급, 24시간): 보안 이슈, 장애 대응
  → ADR 필수, 즉시 처리
  
- 🟡 **Type B** (일반, 1-2주): 새로운 정책, 기준 변경
  → ADR 필수, 팀 검토 후 2-3일
  
- 🟢 **Type C** (경미, 즉시): 문서 정정, 예제 추가
  → ADR 불필요, Owner가 바로 수정

## 💡 작성 팁

### ✅ Do (잘된 예시)

```
❌ 의견: "모델이 너무 느려"
✅ 의견: "Sonnet의 지연시간이 3초 → 불만족" 

❌ 결정: "나중에 좋은 모델로"
✅ 결정: "2026-08-24까지 Haiku vs Sonnet 벤치마크 진행"

❌ 액션: "누군가 가이드 쓸 것"
✅ 액션: "**[이름]** - 모델 선택 가이드 작성 - 2026-08-31"

❌ 근거: "다들 동의했음"
✅ 근거: "비용 60% 절감 + 응답시간 500ms 목표 달성"
```

### ❌ Don't (피할 것)

```
❌ "곧 논의" → ✅ "다음 회의: 2026-08-24"
❌ "누군가 합의" → ✅ "회의에서 [이름1], [이름2], [이름3] 동의"
❌ "뭔가 좋음" → ✅ "테스트 결과 정확도 95% 이상"
❌ "링크 없음" → ✅ "[[관련문서]]로 연결"
```

## 🔄 후속 처리

### 회의 직후 (1시간 이내)
1. 회의록 최종 정리
2. 파일명: `YYYY-MM-DD_주제.md`
3. Commit 및 저장

### 회의 후 (24시간 이내)
1. `해당 파일 경로`에서:
```bash
/claude meeting:process ./2026-08-XX_주제.md
```

2. 자동 처리됨:
   - 요약, 액션 아이템, ADR 생성
   - SSOT 업데이트
   - 팀 알림

### 마감일 추적
- 모든 액션 아이템의 마감일이 Meetings/ACTION_ITEMS.md에 등록됨
- 마감 3일 전 자동 리마인더
