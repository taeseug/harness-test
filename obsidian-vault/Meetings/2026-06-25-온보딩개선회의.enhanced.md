### 안건 1: A/B안 검토

**배경**:
- 온보딩 3단계 42% 이탈 문제
- 2개 개선안 제시: A안 (지연), B안 (단순화)

#### A안 — 결제 정보 입력을 뒤로 미룸

**내용**:
- 가입 완료 후 첫 사용 시점에 결제 정보 요청
- 이탈률 개선 효과 있음

**의견**:
- **최민아(디자인)**:
  - 입장: 가능하나 우려 있음
  - 근거: 이탈은 줄겠지만 결제 미등록 유저가 쌓임
  - 우려사항: 지표는 좋아지지만 실제 매출로 안 이어질 수 있음

- **이지혜(PM)**:
  - 입장: 비판적
  - 근거: A안은 지표는 좋아지는데 실제 매출로 안 이어질 수 있음
  - 판단: 이탈을 뒤로 미루는 것뿐 근본 해결이 아님

**토론 요점**:
- Key point 1: 지표 vs 매출의 불일치 문제
- Key point 2: 결제 미등록 유저 증가 위험
- Key point 3: 단기 수치 개선 vs 장기 비즈니스 영향

#### B안 — 입력 단계 자체를 단순화

**내용**:
- 필수 항목 7개 → 3개로 축소
- 카드 정보 스캔 기능 추가

**의견**:
- **박준서(개발)**:
  - 입장: 찬성하나 일정 우려
  - 근거: 스캔은 외부 SDK 붙여야 해서 2주 정도
  - 제안: 스캔은 1차에서 빼고 항목 축소만 먼저

- **최민아(디자인)**:
  - 입장: 동의
  - 근거: B안이 근본적인 해결책
  - 판단: 항목 축소는 충분히 효과 있을 것

- **이지혜(PM)**:
  - 입장: B안이 더 나음
  - 근거: 근본적 UX 개선

**토론 요점**:
- Key point 1: B안은 근본적인 UX 문제 해결
- Key point 2: 스캔 기능은 2차로 미룰 수 있음
- Key point 3: 항목 축소만으로도 효과 기대 가능
