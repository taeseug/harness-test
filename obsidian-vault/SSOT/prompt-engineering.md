## 🎯 핵심 원칙

### 1. 명확성 우선
```
❌ "코드를 개선해줘"
✅ "이 함수의 성능을 30% 개선하고, 가독성을 유지하세요. 
    목표: O(n²) → O(n log n)"
```

### 2. 구조화
```
❌ 자유형식 텍스트
✅ JSON, Markdown, CSV 같은 명시적 형식 지정
```

### 3. 맥락 최소화
```
❌ 전체 코드베이스 (10K 라인)
✅ 관련 함수만 (100 라인)
```

### 4. 예제 포함
```
❌ 설명만 (한 문장)
✅ 예제 + 설명 (few-shot 학습)
```

## 📊 프롬프트 패턴

### Pattern 1: Zero-shot
명확한 지시문만으로 충분한 경우

**사용 시기**:
- 표준적인 작업 (분류, 요약)
- 모델이 충분히 알고 있는 도메인
- 빠른 응답 필요

**예제**:
```
Q: "이 리뷰의 감정을 classify: [긍정/부동/부정]"
Q: "다음 코드의 시간복잡도는?"
```

### Pattern 2: Few-shot
패턴을 배워야 할 때 (2-5개 예제)

**사용 시기**:
- 특정 형식이나 스타일 학습 필요
- 도메인 특화 작업
- 일관성 있는 출력 필요

**예제**:
```
"다음 패턴으로 변환하세요:

INPUT: "Hello world"
OUTPUT: "hello_world"

INPUT: "MyClass"
OUTPUT: "my_class"

INPUT: "HTTPResponse"
OUTPUT: ???
```

### Pattern 3: Chain-of-Thought
복잡한 추론 필요할 때

**사용 시기**:
- 단계별 사고 필요
- 정확성이 중요
- 검증 가능성 필요

**예제**:
```
"다음을 단계별로 풀어주세요:

1. 문제 분석
2. 접근 방법
3. 단계별 구현
4. 검증

문제: ...
```

## 🛠️ 프롬프트 작성 체크리스트

프롬프트 작성할 때마다:

- [ ] 목표가 명확한가? (한 문장으로 표현 가능한가?)
- [ ] 출력 형식을 명시했는가? (JSON, Markdown, etc.)
- [ ] 필요한 맥락만 포함했는가? (불필요한 정보 제거?)
- [ ] 예제가 있는가? (특히 비표준 작업)
- [ ] 제약 조건을 명시했는가? (길이, 스타일, 등)
- [ ] 토큰 효율을 고려했는가? (불필요한 단어 제거?)

## 📈 프롬프트 최적화 패턴

### 기법 1: 역할 정의
```
"너는 경험 10년의 Python 전문가이고,
보안과 성능에 집중한다.
다음 코드를 리뷰해줘:"
```

### 기법 2: 제약 조건 명시
```
"다음 요구사항을 모두 만족하세요:
- 200자 이내
- 마크다운 형식
- 기술 용어 없이 설명"
```

### 기법 3: 단계별 분해
```
"다음 3단계로 진행하세요:
1. 핵심 아이디어 도출
2. 장단점 분석
3. 권장사항 제시"
```
