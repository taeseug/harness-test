## 🎯 핵심 원칙

### 1. 정보의 중앙 집중화
- 각 정보는 **정확히 한 곳**에만 정의됨
- 다른 곳에서는 링크로 참조
- 변경사항은 **한 곳에서만 수정**

### 2. 의사결정의 추적 가능성
- 모든 주요 의사결정은 `Decisions/ADR-*.md`에 기록
- 왜(Why), 언제(When), 누가(Who), 결과(Outcome)를 명시
- 히스토리 추적으로 진화 과정 파악

### 3. 실행 가능성
- 원칙은 즉시 적용 가능한 수준으로 구체화
- "~하는 것이 좋다" 대신 "~한다"
- 예제와 템플릿 포함

### 4. 버전 관리
```
버전 관리 체계:
- MAJOR: 패러다임 변화 (모델 클래스 변경)
- MINOR: 추가 지침 (새로운 최적화 팁)
- PATCH: 명확화/수정 (오류 수정, 예제 개선)

예: v1.2.3
```

## 💬 프롬프트 엔지니어링

**문서**: `prompt-engineering.md`  
**최종 업데이트**: 2026-08-10

### 핵심 원칙

1. **명확성 우선**: 모호함 제거
2. **구조화**: 형식 명시 (JSON, Markdown 등)
3. **맥락 제한**: 필요한 만큼만 제공
4. **예제 포함**: few-shot 학습 활용

### 프롬프트 패턴

- **Zero-shot**: 명확한 지시문만 필요할 때
- **Few-shot**: 패턴을 배워야 할 때 (2-5개 예제)
- **Chain-of-thought**: 복잡한 추론 필요할 때

→ 자세한 내용: [[prompt-engineering.md]]

## 📈 스케일링 법칙

**문서**: `scaling-laws.md`  
**최종 업데이트**: 2026-08-10

### 핵심 관계식

```
성능 ∝ (모델크기^a) × (데이터크기^b)

일반적 값:
- a ≈ 0.07  (모델 크기 2배 → 성능 5% 향상)
- b ≈ 0.10  (데이터 크기 2배 → 성능 7% 향상)
```

**적용**:
- 데이터 증가가 모델 증가보다 효율적
- 작은 모델 + 많은 데이터 우선

→ 자세한 내용: [[scaling-laws.md]]

**문서**: `error-handling.md`  
**최종 업데이트**: 2026-08-10

### 에러 분류

- **E1**: 입력 검증 실패 → 사용자에게 반환
- **E2**: 모델 한계 → 재시도 또는 상향 요청
- **E3**: 시스템 에러 → 로그 + 알림

**규칙**: 모든 에러는 무시하지 않음 (fail-fast)
